fix(checkers): bind the snapshot stamp to the cached bytes

Equal before/after tree-state samples cannot see a change and revert inside
the warm read, so the stamp was still not provably the state the cached
tree came from. The warm cache now yields a content digest of exactly the
paths and bytes it holds; the same digest is re-derived from the working
tree. Only when the samples agree and the cache bytes are the tree bytes is
that state recorded as the check snapshot; otherwise every requested
checker is recorded FailedToRun/HonestRed with no stamp.

The snapshot decision goes through a private seam so the torn path is
exercised deterministically instead of raced. tests/freshness.rs proves the
cache/disk digest binding including a change-and-revert.

fix(release): AppImage checksum path and standard form

package-appimage.sh redirected inside a subshell that had already cd'd to
the output folder while the file path already carries it: a relative outdir
wrote dist/dist/...sha256 and failed under set -e. The redirect now stays
outside the subshell, and both outer checksums use the standard two-field
form so sha256sum -c reads them (release.yml already reads the first
field). The clean install job now builds into the release workflow's
relative dist shape and asserts the sidecar with sha256sum -c, and the
archive checksum check is no longer ignored with || true.
